工资实时统计（SalaryTime）迭代一需求设计

文档版本：v1.0（口径已确认）
更新日期：2026-11-14
迭代主题：五险一金与个税扣除，从“税前收入”到“本月到手”

============================================================
一、背景与现状
============================================================

当前版本已经具备：
- 固定月薪口径：月薪 = 基础工资 + 绩效工资，按当月周一至周五摊算。
- 加班费额外计入：月末周六双倍基础工资；周末加班自定义起止时间，固定休息
  12:00-13:30、18:00-18:30 不计薪，按时薪 × 实际工时计费。
- 本月预计 = 固定月薪 + 月末周六加班费 + 周末加班费。
- 今日已赚、本月累计、本周累计均为税前口径。
- 设置持久化、托盘、置顶、开机自启、Windows 打包。

当前缺口：
- 用户看到的是税前收入，无法知道扣除五险一金和个税后的实际到手。
- 五险一金比例、缴费基数、个税税率与减免额度因人而异，需要可配置。
- 主界面“本周累计”信息价值有限，可替换为更关心的“本月到手”。

============================================================
二、迭代目标与成功标准
============================================================

目标：
1. 支持配置五险一金：缴费基数可设置，五险与公积金两项可分别按比例或固定金额。
2. 支持手动设置个税税率与每月减免额度（用于专项附加扣除等）。
3. 用“本月到手”替换主界面的“本周累计”卡片，展示税前、扣除与到手。
4. 扣除采用“月末一次性”口径：今日已赚等实时金额继续显示税前，不做逐日扣减。

成功标准：
- 默认参数下，本月到手计算正确（误差 ≤ 0.01 元）。
- 用户可在 2 分钟内完成五险一金与个税配置，并立即看到到手变化。
- 原有税前金额、加班逻辑、设置项不受影响，旧配置可平滑升级。
- 单元测试覆盖五险一金、个税与到手公式；UI 冒烟覆盖设置联动与卡片替换。

============================================================
三、范围与优先级（MVP）
============================================================

P0-1 五险一金配置与计算
- 缴费基数：默认等于固定月薪，可手动设置。
- 两项配置：五险（默认 10.5%）、住房公积金（默认 5%）。
- 每项支持“按比例”或“固定金额”两种模式，可单独启用 / 关闭。
- 仅计算个人缴纳部分；工伤、生育个人不缴，不纳入。
- 默认启用两项，并在设置页提示“默认比例仅作估算，请按实际账单调整”。

P0-2 个税计算
- 个税税率手动设置（百分比，默认 10%）。
- 每月减免额度可设置（默认 0，用于专项附加扣除等）。
- 每月减除费用固定 5,000 元，本期不做修改。
- 本月个税 = max(0, 本月税前收入 − 五险一金 − 5,000 − 每月减免额度) × 税率。
- 不使用累计预扣预缴与七级税率表，保持模型简单、可解释。

P0-3 本月到手展示
- 主界面删除“本周累计”卡片，原位置替换为“本月到手”。
- 本月到手预计 = 本月税前预计 − 五险一金 − 本月个税。
- 卡片副文本展示税前金额或扣除合计，明细在设置页预览中查看。
- 今日已赚、本月累计继续保持税前，不做扣除。

P0-4 配置校验、持久化与兼容
- 比例范围 0-100%，金额、基数、减免额度非负；非法输入拦截并提示。
- 新增配置写入 settings.json，旧版本配置缺少字段时使用默认值。
- 设置页预览新增：本月税前预计、五险一金、本月个税、本月到手预计。

P1（本期不做，记录备选）
- “本年已预扣个税”手动校准。
- 五险分项明细（养老 / 医疗 / 失业）与单位缴纳部分。
- 历史月份归档、工资条、CSV/Excel 导出。

============================================================
四、用户故事
============================================================

US-1 作为用户，我想按自己的缴费基数填写五险一金，让到手估算更接近实际工资。
US-2 作为用户，我想把某个险种改成固定扣款金额，因为公司账单上就是固定数。
US-3 作为用户，我想手动设置个税税率和每月减免额度，用来覆盖专项附加扣除。
US-4 作为用户，我想在悬浮窗直接看到本月到手，而不是本周累计。
US-5 作为用户，我希望今日已赚仍然是税前金额，不要因为扣除逻辑变得难以理解。

============================================================
五、功能需求
============================================================

5.1 五险一金

5.1.1 配置字段
- 缴费基数：
  - 默认空值，表示使用基础工资。
  - 可填写具体金额，用于社保 / 公积金基数与基础工资不一致的情况。
  - 校验：≥ 0，≤ 1e9；空值合法。
- 五险（social）：
  - enabled：是否启用，默认启用。
  - mode：ratio（按比例）或 fixed（固定金额）。
  - ratio：百分比，默认 10.5。
  - amount：固定金额，mode = fixed 时生效。
- 住房公积金（housingFund）：
  - enabled：默认启用。
  - mode：ratio 或 fixed。
  - ratio：百分比，默认 5。
  - amount：固定金额，mode = fixed 时生效。
- 说明文案：仅计算个人缴纳部分；各地比例与基数上下限不同，请按实际账单填写。

5.1.2 计算规则
- 缴费基数 = 配置基数（有值时）或 基础工资。
- 单项月扣款：
  - ratio 模式：缴费基数 × 比例 ÷ 100，四舍五入到分。
  - fixed 模式：直接使用填写金额。
- 五险一金合计 = 五险 + 公积金（启用项之和）。
- 关闭某项即视为 0，不影响另一项。

5.1.3 默认值
- 基数：空（使用基础工资）。
- 五险 10.5%，公积金 5%，均启用、按比例。
- 默认值仅作估算，首次进入设置页时以提示说明“请按实际账单调整”。

5.2 个税

5.2.1 配置字段
- 个税税率：百分比，默认 10%，范围 0-100。
- 每月减免额度：默认 0，≥ 0，用于专项附加扣除等。
- 每月减除费用：固定 5,000 元，只读。
- 不做累计预扣，不内置税率表。

5.2.2 计算公式
- 月度计税基数 = max(0, 本月税前预计 − 五险一金 − 5,000 − 每月减免额度)。
- 本月个税 = 月度计税基数 × 税率 ÷ 100，四舍五入到分。
- 本月税前预计 = 现有 monthProjected（固定月薪 + 月末周六加班费 + 周末加班费），个税按全部税前收入计算，包含基础工资、绩效工资与加班费。
- 说明：该模型为简化估算，税率与减免额度由用户按实际情况填写。

5.2.3 本期假设与限制
- 个税按单月收入计算，不做年度累计预扣与汇算清缴。
- 年终奖、劳务报酬、股权等其它收入不纳入。
- 税率由用户手动维护；政策或收入变化时需自行调整。

5.3 本月到手

5.3.1 计算
- 本月五险一金 = 5.1 的合计。
- 本月个税 = 5.2 计算值。
- 本月到手预计 = max(0, 本月税前预计 − 本月五险一金 − 本月个税)。

5.3.2 展示
- 主界面删除“本周累计”卡片，原位置替换为“本月到手”卡片：
  - 主数值：本月到手预计。
  - 副文本：税前 ¥X（或“已扣 ¥Y”），取决于版面空间。
  - 扣除明细（五险一金、个税）在设置页预览与悬浮提示中展示。
- 今日已赚、本月累计维持税前口径，不显示扣减。
- 月末一次性扣除口径：扣除金额不按日摊销，不改变今日金额的实时跳动。
- 卡片视觉层级与“本月累计”保持一致；到手金额可使用更醒目的颜色。

5.3.3 设置页预览
在现有预览区新增以下行：
- 本月税前预计
- 五险一金（个人）
- 本月个税
- 本月到手预计
并保留固定月薪、工作日日薪、月末周六、周末加班等现有行。

5.4 配置与兼容

- settings.json 新增：
  - insurance：{ base: null | number, social: {...}, housingFund: {...} }
  - tax：{ rate: number, monthlyReduction: number }
- 读取旧配置时：
  - 缺失 insurance / tax 字段使用默认值。
  - 单项缺失按默认项补齐，不覆盖用户已保存的值。
- 保存前做类型与范围校验，非法值回退默认值。
- 恢复默认按钮同时重置五险一金与个税配置。

============================================================
六、界面与交互
============================================================

6.1 主界面
- 保持现有：今日已赚、日进度、本月累计、模式标签、底部日薪 / 时薪。
- 删除：本周累计卡片。
- 替换：原本周累计位置显示“本月到手”卡片。
- 今日已赚、本月累计、本月到手三块信息形成“今天 / 本月税前 / 本月到手”的闭环。
- 窗口尺寸保持 400 × 322，不新增通栏，避免影响拖动与位置记忆。

6.2 设置页
新增两个分组：
A. 五险一金
- 缴费基数（留空 = 月薪）
- 五险：开关 + 模式（比例 / 固定）+ 数值（默认 10.5%）
- 公积金：开关 + 模式（比例 / 固定）+ 数值（默认 5%）
- 当前合计（只读）
B. 个税
- 个税税率（默认 10%）
- 每月减免额度（默认 0）
- 每月减除费用 5,000（只读）
- 本月个税（只读）
- 说明：简化估算模型，税率与减免额度请按实际工资条调整。

6.3 状态与异常
- 输入非法（负数、比例 > 100、金额非数字）：不写入设置，失焦恢复合法值。
- 五险一金合计 ≥ 税前预计时：到手显示 0，并提示“扣除已超过税前收入，请检查配置”。
- 减免额度大于等于计税基数时：个税显示 0，不报错。
- 旧配置升级后首次打开：使用默认五险一金与个税配置，并在设置页展示一次性提示。

============================================================
七、计算示例（默认参数）
============================================================

默认参数：
- 基础工资 20,000，绩效 5,000，固定月薪 25,000。
- 2026 年 11 月含月末周六加班费 1,839.08，本月税前预计 = 26,839.08。
- 五险一金基数 = 20,000（基础工资）。
- 五险 10.5% = 2,100.00
- 公积金 5% = 1,000.00
- 五险一金合计 = 3,100.00
- 个税税率 10%，每月减免额度 0，减除费用 5,000。

示例 1：2026 年 11 月，无手动加班
- 本月税前预计 = 26,839.08（25,000 + 月末周六 1,839.08）
- 月度计税基数 = 26,839.08 − 3,100 − 5,000 − 0 = 18,739.08
- 本月个税 = 18,739.08 × 10% = 1,873.91
- 本月到手 = 26,839.08 − 3,100.00 − 1,873.91 = 21,865.17

示例 2：在上述基础上，11 月有周末加班费 804.60
- 本月税前预计 = 27,643.68
- 月度计税基数 = 27,643.68 − 3,100 − 5,000 = 19,543.68
- 本月个税 = 1,954.37
- 本月到手 = 27,643.68 − 3,100.00 − 1,954.37 = 22,589.31

示例 3：每月减免额度设置为 2,000（专项附加扣除），无手动加班
- 月度计税基数 = 26,839.08 − 3,100 − 5,000 − 2,000 = 16,739.08
- 本月个税 = 1,673.91
- 本月到手 = 26,839.08 − 3,100.00 − 1,673.91 = 22,065.17

说明：示例仅用于验证公式，实际以用户配置的缴费基数、比例与税率为准。

============================================================
八、验收标准
============================================================

1. 默认参数、2026 年 11 月：五险一金 3,100.00，个税 1,873.91，到手 21,865.17，误差 ≤ 0.01。
2. 五险或公积金切换为固定金额后，合计与到手按新金额联动。
3. 关闭五险或公积金后，对应扣款为 0，另一项不受影响。
4. 修改个税税率或每月减免额度后，个税与到手实时联动。
5. 当月加班费同时计入税前预计与个税计税基数，到手相应变化。
6. 今日已赚、本月累计仍为税前；主界面不再展示本周累计。
7. 主界面“本月到手”卡片与本迭代前“本周累计”位置一致，窗口尺寸不变。
8. 旧版 settings.json 加载不报错，缺失字段使用默认值，已有薪资与加班配置不丢失。
9. 设置页修改五险一金 / 个税后，预览与主界面“本月到手”实时联动。
10. 非法输入被拦截，不写入设置；合计超过税前收入时到手为 0 并有提示。
11. 单元测试覆盖：五险一金两项、固定金额、税率、减免额度、到手公式、旧配置兼容。
12. UI 冒烟覆盖：设置项联动、预览数值、本周累计替换为到手、恢复默认。

============================================================
九、不做项（Non-goals）
============================================================

- 不做累计预扣预缴、七级税率表、个税汇算清缴。
- 不计算单位缴纳部分，只展示个人扣除。
- 不做五险分项明细（养老 / 医疗 / 失业），本期合并为“五险”一项。
- 不做社保基数上下限自动判断（各地规则不同，仅做基础校验）。
- 不做专项附加扣除分项管理，本期只支持每月减免额度合计。
- 不做年终奖、股权、劳务报酬等其它收入。
- 不做历史月份归档、工资条、CSV / Excel 导出。
- 不改变今日已赚的税前口径，不做逐日扣除摊销。
- 不做多收入来源、多份工作的合并计税。

============================================================
十、风险与已确认口径
============================================================

风险：
1. 手动税率是简化模型，可能与实际个税存在偏差；用户需按工资条维护税率与减免额度。
2. 各地五险一金比例与基数差异大，默认 10.5% / 5% 只能作为估算示例。
3. 个税政策或税率变化时，需要用户自行调整配置。
4. 主界面用“本月到手”替换“本周累计”，需要确认副文本长度不影响卡片排版。

已确认：
- 五险一金默认启用，缴费基数默认基础工资、可设置。
- 五险默认 10.5%，公积金默认 5%，两项均可改为固定金额。
- 个税采用手动税率 + 每月减免额度。
- 本月到手替换本周累计，窗口尺寸不变。
- 个税税率默认 10%，减免额度默认 0。
